## 4. Architecture: the deepening that was implemented

Full candidate report: `%TEMP%\architecture-review-20261110-1132.html` (6 ranked candidates with before/after diagrams).
**Top recommendation implemented: a single-owner viewport wire contract.**

- **New deep module** `crates/omniport-capture/src/viewport.rs`: `ViewportBatch` / `ViewportRow` own the ICD §2 layout (header size, row stride, reserved word, endianness, bounds, clamping, payload copy, encode and decode). Interface: `read_viewport_batch(start, count)`, `total_packets()`, `rows()`, `encode/encode_to_vec`, `decode(&[u8])`.
- **Deleted duplicate decoders/constants**: the extcap re-parser, the Tauri `fetch_viewport_binary` capacity guess and layout constants, and the capture writer's hand-rolled loop all collapsed onto the module.
- **Frozen cross-language contract**: `fixtures/viewport_v1.json` is generated from the ICD text alone by `fixtures/generate_viewport_fixture.mjs` (an independent oracle, not a snapshot of an implementation). The Rust encoder is asserted in `crates/omniport-capture/tests/viewport_contract.rs`; the TypeScript decoder is asserted against the *same* bytes in `apps/omniport-desktop/src/ipc/viewportDecoder.contract.test.js`. Drift in either language now fails a test instead of a display.
- **ICD completed**: normative bit tables for `pins` and `flags` (§1.1/§1.2) and the reserved-word/total-vs-returned semantics (§2). Before, bit positions existed only as two hand-maintained codebooks in Rust and TS.
- **ADR-007** records the single-owner contract and its consequences (including that viewport serialization copies payloads, which ADR-003's zero-copy claim did not scope).
- **Domain model**: new root `GLOSSARY.md` picks canonical terms (Frame, Row, Viewport, Viewport Batch, Endpoint, Port Path, Route, Topology, Session, Demo Stream) and lists the words to avoid — the codebase used frame/packet/event/row and route/edge interchangeably.

Companion deepening (task-4, implemented by ui-auditor): the desktop viewport window had three owners (App held `totalPackets`, SerialWorkbench held rows/window/gate/epoch, HexMonitorCanvas held `scrollTop` + row math). It is now one framework-agnostic `ViewportSession` module (race tickets, cache-first dedupe, epoch, selection snapshot, auto-scroll, status/error, dispose) with pure range math in `viewportWindow.ts`, consumed via `useSyncExternalStore`; canvases are renderers that emit intents. 29 new DOM-free tests cover the race/dedupe/auto-scroll/clamping behaviour that could not be tested before.

Deletions under the skill's deletion test: the one-line `omniport-hal-posix::throttler` re-export module (interface equals implementation; hal-windows already imported core directly) and `StreamPacketizer::push_chunk_events` (a second framing interface with only a test caller, which disabled CRC with `take()` to work at all).

Also fixed in core during this pass: `TokenBucketThrottler` returned a ~584-year delay for `baud_rate == 0` (f64 infinity saturating on the integer cast) → rate floored; `RoutingGraph::route` called `tokio::spawn` unconditionally and panicked for delayed edges outside a runtime → falls back to immediate delivery.

### Remaining architecture candidates (not implemented — ranked in the HTML report)

1. `Topology` module: daemon `RouteEntry`, core routed edges and the TS edge model are three incompatible shapes; the "gRPC" seam is length-prefixed JSON over TCP and two disagreeing `.proto` files (one annotated stale). ADR-001 conflict.
2. `CaptureStore` seam: daemon adapter vs fixture adapter so fabricated frames can never live in a shipping `run()` and the GUI proves the daemon path.
3. Delete the remaining shallow shells (`fetch_viewport_binary` is now a one-line adapter; remaining HAL getter pairs exist for tests).

### 5.2 CI findings resolved (first GitHub Actions run)

The first CI run (workflow added in Step 6.3, commit `4928b46`) passed the desktop job and failed the Rust workspace job in one Windows-only test. Both that finding and the viewport-wire risk reported with Step 6.4 are now resolved:

1. **`pty::tests::test_pty_endpoint_lifecycle_and_io` was not portable.** It asserted `Path::exists()` on the created symlink. `exists()` *follows* the link, and the Windows mock target (`mock://pts/42`) has no filesystem entry — so the assertion failed on GitHub-hosted runners (where symlink creation succeeds with the runner's privileges) while local developer-mode runs fell back to writing a marker file and passed. The test now checks the link entry itself with `symlink_metadata()` and asserts removal with `is_err()`.
2. **Viewport bytes were JSON-encoded as a byte array.** `Response::ViewportBatch { bytes: Vec<u8> }` serialized as a JSON array of numbers: several-fold wire inflation at 60 Hz and a direct path past the 16 MiB `MAX_FRAME_SIZE` budget. `bytes` now travels base64-encoded, and `Response::viewport_batch` enforces `MAX_VIEWPORT_BATCH_BYTES` (8 MiB raw → ~10.7 MiB base64, inside the 16 MiB frame limit) and returns an explicit 413 error for oversized batches. Tests cover the base64 wire form and roundtrip, at-limit acceptance, oversize rejection, and the frame-budget arithmetic.

## 8. Known gaps (documented, not papered over)

- **com0com pair lifecycle:** *Hardened in Step 6.6* (`crates/omniport-hal-windows/src/com0com.rs`): `Com0ComController::new()` fails loudly with `HalError::Com0ComDriverNotFound` when `setupc.exe` is absent (`new_mock()` is explicit for tests), `create_pair` parses the real `com0com` pair index from `CNCA<N>`/`CNCB<N>` (`setupc install` / `setupc list` fallback), and `remove_pair` runs `setupc remove <N>` with error propagation. **Still HIL-pending:** live `com0com.sys` driver execution on a Windows host with `com0com` installed (recorded in `docs/VV_RTM.md`).
- **POSIX PTY disconnect detection:** *Hardened in Step 6.6* (`crates/omniport-hal-posix/src/pty.rs`): removed the extra slave fd held open in `PtyIo::Unix`, mapped `res == 0` reads to `UnexpectedEof`, and added `ptsname_error` handling direct positive-errno returns (`ptsname_r` on Linux/POSIX) before `errno`. **Still HIL-pending:** Unix compilation and live `/dev/pts/*` `EIO` disconnect verification on Linux/macOS (recorded in `docs/VV_RTM.md`).
- **CUSE backend & UAPI struct layouts:** *Hardened in Step 6.6* (`crates/omniport-hal-posix/src/cuse.rs`): aligned kernel structs to Linux UAPI sizes (`KernelTermios` 36 B, `termios2` 44 B + `BOTHER`, `SerialCounters` 80 B), implemented the `CuseFuseSession` wire protocol (`CUSE_INIT`, `FUSE_OPEN`, `FUSE_READ`, `FUSE_WRITE`, `FUSE_POLL`, `FUSE_IOCTL`/`FUSE_IOCTL_RETRY`, `FUSE_INTERRUPT`, `FUSE_DESTROY`), gated `linux_cuse` `/dev/cuse` FUSE wiring, and made `CuseEndpoint::open` fail loudly on non-Linux hosts (`open_mock()` for tests). **Still HIL-pending:** Linux compilation and live `/dev/cuse` kernel HIL verification (recorded in `docs/VV_RTM.md`).
- **RFC 2217 negotiation replies:** *Closed in Step 6.6* (`crates/omniport-net/src/rfc2217.rs`, `tcp.rs`): implemented RFC 1143 `Rfc2217Negotiator` supporting `COM_PORT_OPTION`, `TRANSMIT_BINARY`, and `SUPPRESS_GO_AHEAD` while rejecting unsupported options cleanly and wired loop-free replies into `TcpEndpoint::from_stream`.
- **Lua sandbox residuals:** *Closed in Step 6.6* (`crates/omniport-script/src/engine.rs`, `bindings.rs`, `error.rs`): enforced `ScriptConfig::max_memory_bytes` (`4 MiB` default) via `Lua::set_memory_limit`, mapped C-function OOM (`string.rep`, `table.concat`) to `ScriptError::MemoryExceeded` with double-GC cleanup, and bounded `serial.send` frames/tables (`MAX_SERIAL_SEND_BYTES = 1 MiB`) before Rust allocations.
- **Daemon hardening:** *Bounded in Step 7.2* (`crates/omniportd/src/server.rs`, `main.rs`): loopback bind by default with `--allow-remote` required for non-loopback addresses; `--max-connections` (default 64) rejects excess clients with an explicit 503; `--idle-timeout-secs` (default 30) closes idle connections silently to preserve request/response framing; `--request-timeout-secs` (default 10) returns a 503 on handler timeout; `--max-requests-per-sec` (default 200 per connection) returns 429 and closes. Tests cover idle close, connection cap, 429, oversized frames, and shutdown under idle load; see `docs/ICD.md` §3.4. **Remaining:** the control plane is still unauthenticated — `--allow-remote` assumes a trusted/authenticated network or tunnel until TLS/auth is added. ADR-0001's gRPC/UDS mismatch was closed in Step 6.8 via `docs/adr/0008-json-tcp-daemon-control-plane.md`.
- **Scenario-runner semantics:** *Completed in Step 7.3* (`crates/omniport-cli/src/scenario/validate.rs`, `runner.rs`, `docs/SCENARIO.md`): unsupported `tcp_server`/`tcp_client`/`udp` endpoints (and their `address` field) are rejected at load time instead of silently skipped; explicit route ids are rejected because the core allocates canonical ids; undeclared endpoint references, unknown config/step keys, and vacuous steps (`send` with both/neither payload form, `set_pins` with no flags, `assert_pins`/`assert_metrics` with no expectations, bare `expect`) fail before execution; `AssertPins.timeout_ms` is now honoured by polling tracked pin state every 10 ms, and pins applied asynchronously by script endpoints are mirrored so the timeout can observe them. The root `.omniport.yaml` was updated (route `id` removed) and remains green end-to-end.
- **Architecture candidate 1** (`Topology`) was completed in Step 6.5: `omniport_core::topology::Topology::apply(Request) -> Result<Response>` now owns endpoint/route lifecycle, ID allocation, live-endpoint/fault validation, and incremental `RoutingGraph` reconciliation across `omniportd` and `omniport-cli` (`ScenarioRunner`); `omniport_proto::SerialConfigDto` aliases `omniport_core::SerialConfig` and `GetTopology` exposes canonical `Route` + `EndpointInfo`; the TS desktop topology types and helpers unify on the canonical route shape and resolve real endpoint IDs instead of hardcoded placeholders; both `.proto` files (`proto/omniport.proto` and `crates/omniport-proto/proto/omniport.proto`) were deleted and the 4-byte BE length-prefixed JSON over TCP transport is documented in `docs/ICD.md` §3 (ADR-0001 and ADR-0003 were superseded by ADR-0008 and ADR-0009 in Step 6.8). Routing all `CreateVirtualPair` calls through `RoutingGraph` exposed O(N²) full-`HashMap` RCU clones in `crates/omniport-core/src/routing.rs` (exhaustion tests took 2691.95s in `omniport_core` and 2248.33s in `omniportd`); replacing `RoutingTable` storage with a persistent 4-level `u16` radix trie (`TrieMap`) + incremental `Topology` edge ownership cut those suites to 2.88s and 2.63s respectively.
