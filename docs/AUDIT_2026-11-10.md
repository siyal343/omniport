## 4. Architecture: the deepening that was implemented

Full candidate report: `%TEMP%\architecture-review-20261110-1132.html` (6 ranked candidates with before/after diagrams).
**Top recommendation implemented: a single-owner viewport wire contract.**

- **New deep module** `crates/omniport-capture/src/viewport.rs`: `ViewportBatch` / `ViewportRow` own the ICD §2 layout (header size, row stride, reserved word, endianness, bounds, clamping, payload copy, encode and decode). Interface: `read_viewport_batch(start, count)`, `total_packets()`, `rows()`, `encode/encode_to_vec`, `decode(&[u8])`.
- **Deleted duplicate decoders/constants**: the extcap re-parser, the Tauri `fetch_viewport_binary` capacity guess and layout constants, and the capture writer's hand-rolled loop all collapsed onto the module.
- **Frozen cross-language contract**: `fixtures/viewport_v1.json` is generated from the ICD text alone by `fixtures/generate_viewport_fixture.mjs` (an independent oracle, not a snapshot of an implementation). The Rust encoder is asserted in `crates/omniport-capture/tests/viewport_contract.rs`; the TypeScript decoder is asserted against the *same* bytes in `apps/omniport-desktop/src/ipc/viewportDecoder.contract.test.js`. Drift in either language now fails a test instead of a display.
- **ICD completed**: normative bit tables for `pins` and `flags` (§1.1/§1.2) and the reserved-word/total-vs-returned semantics (§2). Before, bit positions existed only as two hand-maintained codebooks in Rust and TS.
- **ADR-007** records the single-owner contract and its consequences (including that viewport serialization copies payloads, which ADR-003's zero-copy claim did not scope).
- **Domain model**: new root `GLOSSARY.md` picks canonical terms (Frame, Row, Viewport, Viewport Batch, Endpoint, Port Path, Route, Topology, Session, Demo Stream) and lists the words to avoid — the codebase used frame/packet/event/row and route/edge interchangeably.

Companion deepening (task-4, implemented by ui-auditor): the desktop viewport window had three owners (App held `totalPackets`, SerialWorkbench held rows/window/gate/epoch, HexMonitorCanvas held `scrollTop` + row math). It is now one framework-agnostic `ViewportSession` module (race tickets, cache-first dedupe, epoch, selection snapshot, auto-scroll, status/error, dispose) with pure range math in `viewportWindow.ts`, consumed via `useSyncExternalStore`; canvases are renderers that emit intents. 29 new DOM-free tests cover the race/dedupe/auto-scroll/clamping behaviour that could not be tested before.

Deletions under the skill's deletion test: the one-line `omniport-hal-posix::throttler` re-export module (interface equals implementation; hal-windows already imported core directly) and `StreamPacketizer::push_chunk_events` (a second framing interface with only a test caller, which disabled CRC with `take()` to work at all).

Also fixed in core during this pass: `TokenBucketThrottler` returned a ~584-year delay for `baud_rate == 0` (f64 infinity saturating on the integer cast) → rate floored; `RoutingGraph::route` called `tokio::spawn` unconditionally and panicked for delayed edges outside a runtime → falls back to immediate delivery.

### Remaining architecture candidates (not implemented — ranked in the HTML report)

1. `Topology` module: daemon `RouteEntry`, core routed edges and the TS edge model are three incompatible shapes; the "gRPC" seam is length-prefixed JSON over TCP and two disagreeing `.proto` files (one annotated stale). ADR-001 conflict.
2. `CaptureStore` seam: daemon adapter vs fixture adapter so fabricated frames can never live in a shipping `run()` and the GUI proves the daemon path.
3. Delete the remaining shallow shells (`fetch_viewport_binary` is now a one-line adapter; remaining HAL getter pairs exist for tests).

## 6. Design review (`emil-design-eng`) — applied

| Before | After | Why |
| :--- | :--- | :--- |
| no motion tokens | `--ease-out: cubic-bezier(.23,1,.32,1)`, `--ease-in-out`, 120/150 ms | built-in CSS easings feel weak and sluggish |
| no press feedback | `.op-btn` / `.op-tab` `:active { transform: scale(.97) }` | the interface must acknowledge a press |
| hover styles ungated | `@media (hover:hover) and (pointer:fine)` | touch taps otherwise leave sticky hover states |
| `prefers-reduced-motion` ignored | media query drops transform motion, keeps colour/opacity | motion-sickness accessibility |
| no visible focus | `:focus-visible` 2 px ring | keyboard operability |
| no `transition: all` audit | property-specific transitions only (0 occurrences of `transition: all`) | avoid animating layout/paint |
| theme toggle showed the theme you would switch to | shows the current theme + `aria-pressed` + title | a toggle reflects state, not an action |
| hardcoded topology/telemetry palette | tokenised CSS vars for both themes | light mode was half-broken |
| proportional digits in metrics | `font-variant-numeric: tabular-nums` | readouts stop jittering |
| blank canvas on empty capture | "WAITING FOR CAPTURE DATA" empty state | no unexplained void |
| idle canvases repainted at 60 Hz | dirty-check paint loops | CPU/battery |
| duplicated hex JSX per tab | one shared `HexView` | one implementation, fewer drift bugs |
| fake data unlabelled | DEMO STREAM badges + `capture_status.demo_mode` | an operator must never mistake demo for live |

## 8. Known gaps (documented, not papered over)

- **com0com pair lifecycle:** `remove_pair` passes our synthetic pair id where com0com expects its pair index, and `create_pair` silently reports success without the driver. Needs com0com HIL, not unit tests.
- **POSIX PTY disconnect detection:** an extra slave fd kept open for termios polling means the master never sees `EIO` when the client closes; `ptsname_r` uses the wrong error channel. Unix-only.
- **CUSE backend is still a mock:** no `/dev/cuse` FUSE wiring, and `TCGETS`/`TIOCGICOUNT` struct sizes differ from the kernel (FR-103 gap).
- **RFC 2217 negotiation replies** are not sent (incoming WILL/DO are decoded then ignored); needs a negotiation state machine.
- **Lua sandbox residuals:** C-function allocations (`string.rep`, `table.concat`) are not fuel-limited and no mlua memory limit is set.
- **Daemon hardening:** no per-connection read timeout or connection cap (slowloris), and ADR-001's gRPC/UDS transport is still length-prefixed JSON over TCP.
- **Architecture candidates 1–2** (`Topology`, `CaptureStore` seam) remain follow-ups; the GUI still owns an in-process capture store seeded in debug builds until the daemon client is wired.
